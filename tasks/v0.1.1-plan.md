# Implementation Plan: NanoEvolve v0.1.1 Release Hardening

## Overview

Harden the validated NanoEvolve v0.1 core for public repository use without changing its evolution algorithm. Work proceeds through test-first slices and ends with wheel/source-distribution inspection plus clean-environment installation.

## Dependency Order

```text
version API + module entry
        |
        v
package metadata + py.typed + manifest
        |
        v
contributor/security/changelog docs
        |
        v
release_check.py
        |
        v
GitHub Actions + package acceptance
```

## Tasks

### Task 1: Version and module entry points

**Acceptance criteria:**
- [x] `nanoevolve.__version__` is non-empty.
- [x] Installed metadata and exported version agree.
- [x] `python -m nanoevolve --version` and `nanoevolve --version` succeed.

**Verification:** `python -m unittest tests.test_version_entrypoints -v`

### Task 2: Distribution metadata and contents

**Acceptance criteria:**
- [x] `pyproject.toml` has truthful classifiers and keywords.
- [x] Runtime dependency list remains empty.
- [x] `py.typed` is included in the wheel.
- [x] Source distribution includes docs, examples, tests, and task records.

**Verification:** build wheel/sdist and inspect archive members.

### Task 3: Contributor-facing documentation

**Acceptance criteria:**
- [x] `CONTRIBUTING.md`, `SECURITY.md`, and `CHANGELOG.md` exist.
- [x] English and Chinese README release sections remain aligned.
- [x] No author, license, repository URL, or contact address is invented.

**Verification:** documentation checks in `release_check.py`.

### Task 4: Release checker

**Acceptance criteria:**
- [x] Runs unittest discovery and compileall.
- [x] Checks README parity, required concepts, LOC budget, metadata, and release files.
- [x] Returns non-zero with a clear message when an invariant fails.

**Verification:** `python scripts/release_check.py`

### Task 5: Continuous integration

**Acceptance criteria:**
- [x] CI covers Ubuntu 3.11/3.12/3.13, Windows 3.12, and macOS 3.12.
- [x] Package job builds and inspects wheel/sdist.
- [x] Package job installs the wheel and runs deterministic smoke checks.

**Verification:** local YAML and command-surface review; equivalent local build acceptance.

### Task 6: Final package acceptance

**Acceptance criteria:**
- [x] Existing and new tests pass.
- [x] Wheel and sdist build successfully.
- [x] Clean venv installs the wheel with zero runtime dependencies.
- [x] Installed module entry point, demo, best, and inspect work.

**Verification:** full local release acceptance commands.

## Risks

| Risk | Mitigation |
| --- | --- |
| Version drift | Resolve runtime version from installed metadata. |
| Platform-specific subprocess failures | Exercise major OS/Python combinations in CI. |
| Incorrect distribution contents | Inspect wheel and sdist member names. |
| Release docs overclaim identity or safety | Enforce explicit absence and security-boundary checks. |
